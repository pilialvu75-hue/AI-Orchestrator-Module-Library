## Consumer integration

Use the Git dependency with `path: packages/aivexus_original_updater` and an exact reviewed commit SHA. Import `package:aivexus_original_updater/aivexus_original_updater.dart`. Instantiate the original UpdateChecker with your own manifestUrl, githubOwner, githubRepo, targetPlatform and desktop asset names; initialize preferences and comparator. Desktop hosts can use configurePlatformUpdateServices with their explicit endpoints and all three asset names. Android hosts instantiate UpdateManager with the checker and AndroidIntentHandler. Do not point VoiceBridge at Riserva's manifest or installer.

The module has no Beta Access registration requirement. The Android MethodChannel adapters are preserved, but the host must implement the original native background_downloads and android_intents channels (including verified APK handling, FileProvider and install confirmation). See [original MainActivity](https://github.com/pilialvu75-hue/Ai-orchestrator-riserva/blob/5d5a3905ceced2c01c8f1d4a8c44ac75d9215fe0/android/app/src/main/kotlin/com/aiorchestrator/MainActivity.kt) and [BackgroundDownloads](https://github.com/pilialvu75-hue/Ai-orchestrator-riserva/blob/5d5a3905ceced2c01c8f1d4a8c44ac75d9215fe0/android/app/src/main/kotlin/com/aiorchestrator/BackgroundDownloads.kt). Do not transplant unrelated MainActivity functionality. The original Android settings page is available via `package:aivexus_original_updater/ui/update_settings_page.dart` as `UpdateSettingsPage(updateManager: manager)`. It preserves the original UI, original localization keys and English fallback; originally hard-coded labels are unchanged. The host must still supply native Android channels and supported MaterialApp locales. No physical OTA or rollback validation claimed.

## Android integrity preview (issue #401)
`apk_sha256` (alias `apkSha256`) is preserved in manifest/cache and GitHub asset digest. When provided it is checked against streamed file bytes, including resumed/pending APKs and immediately before install. New Android consumers should set `requireApkSha256: true` on both UpdateChecker and UpdateManager; missing checksum fails closed and the manager disables its legacy debug signature bypass. Existing consumers keep compatibility by default; no change to pinned dev.1 or desktop install flows. Physical OTA validation is still required.
